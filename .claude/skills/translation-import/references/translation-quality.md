# 底稿、規則與中文閱讀

順序是：沿用中文原稿 → 核對規則與定案詞 → 登記修改 → 整段映射。這是同一份譯文的連續整理；EN 供核對語意，不是中文句型範本。

## 中文來源與底稿

簡體原稿先用 OpenCC `s2twp` 轉繁，轉換檔存為 `_incoming/<book>/_source/<檔名>.s2twp.txt`；繁體原稿直接處理。**底稿由原稿逐段產生**，修改限於下文「允許的修改類別」，每處登記；原稿通順且與 EN、定案詞無衝突的句子一字不動，不逐詞重譯，也不為了「更順」重寫。

底稿製作順序固定為：原稿 → 底稿（含修改登記）→ `draft_diff.py` 檢查 → 映射。映射後才寫的中文不得回填成底稿；需要修句時先改底稿再重新映射。以映射結果反推底稿，會讓「映射文字須在底稿中」的檢查失去意義。

底稿用 `### English Name` 分條，內文是完整可讀中文，不填 HTML 槽位。原稿段落與 EN 區塊的對應（一對一、合併、拆分、順序不同）要在修改登記中留下。底稿中若有連結名、小標、表頭，使用最終定案中文，讓映射可見文字仍能對回底稿。

原稿與 EN 的差異記錄：`欄位／EN 原句／原稿原句／提出的底稿／原因／待裁定狀態`，中英文並列。已裁定例外依其語境使用；未裁定時保留問題供預覽。原稿通順但與 EN 有出入、又不影響規則的措辭（例如 `小物件` 對 `implement`），保留原稿並列入預覽的「保留項」，由使用者決定是否改。

## 規則核對

逐句檢查：

- 誰可以或必須做什麼；you、target、ally 等指涉是否明確。
- 觸發時點、前置條件、距離、可見性及目標資格。
- 單一或複數、所有或任一、and 或 or、能否選擇、否定範圍。
- 檢定／豁免的屬性、DC、傷害／治療骰、加值、數值上限。
- 動作種類、資源消耗、次數、恢復條件、持續時間及例外。

自然語序不得弱化條件、改變時點、遺失限制或引入 EN 沒有的規則。疑似上游矛盾列出證據和修訂提案，不用流暢度掩蓋。

## 優先序

用字衝突時由上往下取第一個有定論的來源：

1. 使用者裁定（`conventions.md` 的裁定表與當次對話的明示）。
2. Weblate `terms`；法術名則取 Weblate **現行**名稱（`spell_names.py`），不取 repo 或舊 `spells-glossary`。
3. 同語境 Weblate 已接受的譯文（含 `spells-glossary` 的既有法術描述）。
4. 原稿用字。
5. `lang/zh-tw.json`（介面用詞，只作缺詞後備）。
6. 自行翻譯。

第 4 項在第 2、3 項之後：原稿與 terms 或現行名稱衝突時改用 terms。使用者說「已有翻譯、差異不大就不要改」時，指的是 terms 沒有定論、也沒有與 EN 衝突的措辭；它不放寬第 1–3 項。

## 允許的修改類別

底稿相對原稿只能做這六類修改，每處登記 `原→新｜類別｜理由`：

| 類別 | 範圍 | 例 |
|---|---|---|
| 轉換修正 | s2twp 或簡繁轉換造成的誤字、地區用語 | 觸控→觸摸、著裝→穿戴、併→並、制以→製以、同型別→同類型、訂本→書卷、鍾→鐘 |
| 定案詞 | 優先序第 1–3 項的詞與已裁定句式 | 發充能→點充能、施展→施放、如果→若、take→承受、以下→下列、法器→施法法器、X系→X學派、法術名依現行 |
| 規則 | 原稿與 EN 語意不符（條件、對象、數值、範圍、時點、單位、漏譯、誤譯） | 「宣佈結果之前」→「其效應生效前」、鋼→鐵 |
| 使用者裁定 | 使用者針對該詞或該句的裁定 | 稀有度不寫、人皮保留、亡靈→不死生物 |
| 句式 | `conventions.md` 的句式表 | 作為一個動作→你可以採取一個動作、「30內」→位於你30呎內 |
| 禁用字 | validate 會擋的格式慣例 | 它→其／重複名詞 |

其餘措辭（「在被找到時，包含了」「你持握這本書時」「那麼此次攻擊失手」…）原稿通順且與 EN 無衝突時一字不動。不屬於以上六類的改動，先回到原稿用字。

登記內容就是預覽的「修改」欄；`draft_diff.py` 的差異片段是檢查依據，片段沒有對應登記者視為未登記。

## terms 的套用範圍

- `terms` 的詞條包含**普通動詞與片語**（take、attack roll、immediately after、On a hit…），不只專有名詞；命中時同樣套用。
- EN 的詞形變化（takes／taking／took）算命中；`terms_check.py` 會展開詞形。
- 首字大寫的單字詞條（Hide、Magic、Attack）在句中出現時算命中，句首出現則人工判斷。
- 命中但語意不同（例如 `It takes 10 minutes` 的 take 是「需要」，`take on a semblance` 的 take 是「呈現」，`fiend hide` 的 hide 是獸皮）時，在 `ack.json` 登記一句理由。登記必須逐條，不寫「全部一般用字」。
- `terms` 的中文含 `…` 時，代表兩端詞之間接其他內容（緊接在…後）。
- 語境專用例外在 `conventions.md` 的「已裁定同詞多義」；沒有列出者不自行例外。

## 無原稿內容的來源順序

原稿沒有的條目、段落或欄位文字，依序處理：

1. **Weblate 既有譯文**：用 `weblate.py` 或 API 以 EN 原句查詢（`/api/units/?q="<原句片段>"`），看 `dnd-5e-2024-zh-tw` 各 component、`spells-glossary` 與各書 project 是否已有同句譯文。EN 逐段相同者原樣沿用，只改定案詞、禁用字與已有裁定。
2. **相近既有譯文**（例如 PHB 現行法術的對應段落）為底改寫，登記差異。
3. **自譯**：句式與詞彙沿用已查到的組成詞。

三種都標 `source=supplement`，`basis` 寫明來源與差異，預覽逐項列出。讀取失敗不算「查無既有譯文」。

## 簡繁轉換誤字

`s2twp` 對下列詞會產生不合台灣用法的結果，轉換後先檢查：觸控、著裝、併、制以、同型別、訂本、擬合件、鍾、軟件類詞。這些修改歸「轉換修正」，且隨時補充。

## 術語與句式來源

名稱與句式的細部來源（優先序見上節；此表只補充各類內容去哪裡找）：

| 要決定的內容 | 來源順序 |
|---|---|
| 規則術語、普通動詞與片語 | 使用者裁定／語境例外 → Weblate `dnd-5e-2024-zh-tw/terms` → 相關既有譯文 → `lang/zh-tw.json` 後備 |
| 法術名（含 `@UUID` 的可見標籤） | 使用者裁定 → Weblate 現行名稱（`spell_names.py`，先 PHB project 再 dnd5e） → 舊版 `spells-glossary`（僅後備） |
| 其他專有名稱、UUID 可見標籤 | 使用者裁定 → 該 UUID／EN key 現行 2024 Weblate 中文名稱 → 專案 2024 中文名稱 |
| 中文句式 | 使用者句式裁定 → 同語境 Weblate 已接受譯文 → `conventions.md` 及相關既有語料 |

魔法物品的額外名稱來源與已裁定例外見 [conventions.md](conventions.md)。名稱保持完整；內含規則詞有衝突而無例外時列待確認，不自行改名。複數與大小寫可對回已確認單數詞條；語境不明時不作模糊命中。

### 每批取得現行資料

```bash
python $S/weblate.py samples <project> <component>
python $S/build_index.py --skip-book <book> --out <批次>.term_index.json
python $S/spell_names.py --out spell-names.json
```

索引按 `index['terms']`、`index['entry_names']`、`index['spells_glossary']`、`index['aliases']` 分區查。`aliases` 只將原稿別名對回 EN，不定中文譯名。`entry_names` 來自 repo，不代表 Weblate 現行名稱；法術名以 `spell_names.py` 為準。句式範本的舊譯名不能覆蓋 `terms`。

**讀取工具有界線**：`paged()` 遇到失敗會停止，索引可能為空或不完整。建立索引不等於核實來源；先核對讀取是否成功（筆數合理），失敗記「術語集未核實」，不能記「查無術語」。

### 三方並列比對

每批執行三個比對，輸出都放進預覽：

1. `terms_check.py`：`terms` ＋ 現行法術名 ↔ EN 可見文字 ↔ 底稿（硬性，須回傳 0）。
2. `lang_compare.py`：`lang/zh-tw.json` ↔ 底稿；「無」的項目逐條說明採用或不採用的理由。
3. `usage.py`：只在同詞多義或需要 `terms` 沒有定論時，列出既有譯文用量與例句供使用者裁定；用量不覆蓋 `terms` 或裁定。

`terms_check.py` 的 ❌ 先修底稿；確為一般用字者才在 `ack.json` 登記理由。使用者裁定與 lang 衝突時，依裁定同步修改 lang 並記入 `Changelog.md`。確認所有適用來源都無既有中文時，才依「無原稿內容的來源順序」自譯，逐欄記 EN、中文及依據，標待確認；不因補翻而自動新增正式術語或上傳。

## 中文通讀

先遮住 EN，獨立閱讀底稿及最終中文。確認讀者能一次理解主體、修飾對象及條件與結果；必要時將條件放在動作之前、把修飾語靠近被修飾內容，或使用自然的「當⋯時」「若⋯」句型。以實際語境判斷，不另立一套所有句子都必須套用的固定語序。

例如 EN `You gain <em>advantage</em> on <strong>saving throws</strong>.`，中文可以是「你進行<strong>豁免</strong>時具有<em>優勢</em>。」句內格式隨完整中文詞組移動，保留其包覆對象。

通讀後再對 EN 檢查規則、對底稿檢查映射。若需要改句，先改底稿再映射，不在 JSON 裡另造中文。文字相似度可以協助定位大量改動，不能代替語意與閱讀驗收；機械檢查也無法證明中文自然。
