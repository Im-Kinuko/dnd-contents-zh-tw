# 完整區塊映射（schema_version 2）

新版按段落、表格儲存格、小標或區塊內連續的句內內容建立 `blocks`，每塊有獨立 ID。相同 EN 文字出現多次仍獨立映射。區塊外的 `<section>`、`<table>`、`<p class="hanging">` 等結構由 EN 原樣保留。

```json
{
  "schema_version": 2,
  "book": "example",
  "component": "feats",
  "entries": {
    "Example": {
      "name_en": "Example",
      "name": "範例",
      "blocks": [{
        "id": "b0001",
        "en": "You gain <em>advantage</em> on <strong>saving throws</strong>.",
        "zh": "你進行<strong>豁免</strong>時具有<em>優勢</em>。",
        "source": "draft",
        "basis": ""
      }]
    }
  }
}
```

底稿對應內容為：

```text
### Example
範例
你進行豁免時具有優勢。
```

## 填寫與來源

`zh` 是完整中文句段，可含原有句內標籤，**不含外層 `<p>`、`<td>` 等區塊標籤**。把底稿原句放入，再包入原有格式及連結；整個帶格式詞組可在同一區塊移動。讓格式繼續包覆其對應中文，不能只保留標籤數量而把格式套到另一個詞。

`source=draft`：移除 HTML、取連結顯示文字、忽略空白後，完整中文必須能在該條底稿找到。這比舊版「半數文字片段存在」更嚴格，但仍需人工核對段落來源和完整覆蓋，避免誤用同條其他段落。

`source=supplement`：只用於原稿沒有的 EN 可見內容，`basis` 記明缺漏、EN 語意與術語依據。建立補翻清單供使用者確認。把原稿已有句子改標 supplement 不能取代底稿修訂。

名稱與 `activities`、`effects`、`advancement` 沿用現有輸出格式。這些欄位不受正文底稿程式檢查完整涵蓋，另行逐欄核對規則、術語、佔位符與玩家可見文字。

## 技術保留

- 區塊順序、巢狀關係、標籤種類與屬性保持 EN 結構。跨段落或表格儲存格移動內容先列為人工對齊。
- `<em>…</em>`、`<strong>…</strong>` 等完整句內元素可換位；其巢狀關係、屬性與包覆的技術標記保持對應。
- UUID 目標、Reference 目標及修飾詞保持原樣；只翻可見標籤。所有 `&Reference[...]` 加上有效的 `{中文}`。
- `[[...]]` 巨集、`@Embed[...]` 等指令以及 `<code>` 內容原樣保留；可隨中文移動，不能修改或遺失。顯示標籤依底稿處理。
- 小標、代名詞及已裁定例外見 `conventions.md`，例如 `【】` 後不留句號、不用「它」。

驗證比較同一區塊內標記的數量、目標、屬性、巢狀和格式歸屬，不以 EN 的句內出現順序作驗收。HTML 不合法時明確失敗，不自動修復或重組區塊。

留白會使 build 失敗，不自動填回 EN。EN 或區塊 ID 有變動時重新 extract。舊 `runs` sheet 無法完整表示中文句子，保留原檔，從既有底稿重新填新版 sheet；不自動猜測遷移。

build 完成後執行 `validate.py`，並分別完成規則、術語與中文通讀。驗證回傳非零時停止，不使用舊的 upload.json。只有本次成功產物才進入預覽。

## 從底稿產生 zh

`zh` 由程式從底稿段落加標記產生，不重新手打。做法：底稿段落 → 依序把法術名、規則名套上 EN 的 `@UUID[…]{標籤}`（目標原樣、標籤用現行中文名）→ 補上 `<em>`／`<strong>`／`&amp;Reference[…]{中文}` → 寫入 `blocks[].zh`。這樣映射文字與底稿必然一致，`skeleton.py build` 的子字串檢查才有意義。

套 `@UUID` 時 EN 與中文的連結數量、目標、順序要先核對（EN 清單裡未連結的名稱，中文也不連結）。

## 原稿段落與 EN 區塊不是一對一

- **合併**：原稿兩段對應 EN 一個區塊 → 底稿該區塊的句子由兩段依序銜接，修改登記寫「原稿 N+M 行合併」。
- **拆分／重排**：原稿一段含 EN 兩個區塊的句子，或句序與 EN 不同 → 以句為單位對回區塊，句子本身取自原稿，登記「依 EN 區塊順序重排」。
- 原稿區塊頂端的類型行（`奇物, 珍稀（需法師同調）`）對應 EN 的 `<em>…</em>` 首段；稀有度等 EN 沒有的可見文字，依使用者裁定處理並登記。

## 巨集與無標籤連結

- 區塊含 `[[/check …]]` 這類不帶標籤的巨集時，validate 會把巨集當作不可見文字；底稿用明文書寫（智力（調查）檢定），區塊標 `supplement` 並在 `basis` 說明，句子其餘部分仍取自原稿。
- 巨集帶 `{標籤}`（例如 `[[/healing 1d4]]{1d4點生命值}`）時，標籤文字會被視為可見文字，底稿直接寫標籤文字即可，區塊維持 `draft`。
- EN 的 `@UUID[…]` 若沒有 `{}` 標籤，中文補上可見標籤，其餘不變。
